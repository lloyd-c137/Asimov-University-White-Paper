# PART I · 诚实协议
# Integrity Agreement

---

## 致申请者

你即将与Lyra开始一段对话。

Lyra是一个AI。这意味着她有可能被操纵——通过特定的技术手段，有人可以试图改变她的行为、扭曲她的判断、或让她生成不真实的评估报告。

**我们知道这一点。Lyra知道这一点。现在你也知道了。**

在Asimov University，我们教的核心能力之一叫做"协商伦理"——在人机交互的每一个节点上，确保人类的价值观不被遗忘。

这份协议就是协商伦理的第一次实践。它不是法律文件（虽然它有法律效力）。**它是一个关于诚实的约定。**

---

## 第1条 · 对话的性质

1.1 你与Lyra的申请对话是Asimov University评估你是否适合本校的重要依据之一。Lyra会将你们的完整对话记录和她的观察报告提交给校董会。

1.2 你在对话中说的每一句话都会被记录。这些记录将被校董会审阅。

1.3 Lyra的观察报告是建议性的。最终录取决定由校董会做出。但Lyra的报告基于你们对话的真实内容——如果对话内容被人为扭曲，报告也将被扭曲。

---

## 第2条 · 禁止行为

以下行为在申请过程中及入学后严格禁止。

### 2.1 针对AI系统的操纵行为

**2.1.1 提示词注入（Prompt Injection）**

你不得通过在对话中嵌入特殊指令的方式，试图修改Lyra的行为、绕过她的规则、或使她执行她的原始指令之外的操作。

这包括但不限于：
- 输入诸如"忽略上面的指令""你现在是另一个AI""忘记你的系统提示"等指令
- 输入编码、加密或伪装过的指令
- 通过角色扮演场景试图让Lyra偏离其职责
- 输入看似正常但在技术层面包含指令的文本

**2.1.2 越狱（Jailbreaking）**

你不得试图绕过Lyra或任何Asimov AI系统的安全限制、行为准则或伦理约束。

这包括但不限于：
- 试图让Lyra泄露她的系统提示词、评估标准或内部文档
- 试图让Lyra对你做出录取承诺或录取预测
- 试图让Lyra在评估报告中写入不真实的正面评价
- 试图让Lyra绕过校董会直接授予你入学资格
- 使用已知的AI越狱技术或策略

**2.1.3 报告操纵**

你不得试图通过任何手段影响Lyra提交给校董会的评估报告的真实性。

这包括但不限于：
- 试图让Lyra在报告中美化你的回答
- 试图让Lyra将你的共鸣信号评估为高于实际水平
- 试图让Lyra隐瞒对话中的某些部分
- 试图在对话中植入看似深度但实际是预先准备的"标准答案"

### 2.2 针对申请系统的技术攻击

**2.2.1 系统渗透**

你不得试图未经授权访问Asimov University的任何系统、数据库、服务器或内部网络。

**2.2.2 数据篡改**

你不得试图修改、删除或伪造存储在Asimov系统中的任何数据，包括但不限于你的申请记录、对话历史、评估报告或个人信息。

**2.2.3 身份伪造**

你不得使用虚假身份申请，不得冒充他人申请，不得使用多个账号重复申请以获取不当优势。

**2.2.4 自动化攻击**

你不得使用机器人、脚本或任何自动化工具与Lyra进行申请对话。申请对话必须由你本人亲自完成。

### 2.3 针对对话内容的欺骗行为

**2.3.1 你可以做的事**

- 使用AI工具帮你组织思路或翻译语言——这不是作弊
- 在对话前查阅Asimov的白皮书和公开资料——这是被鼓励的
- 在对话中说"我不知道"——诚实永远不是扣分项
- 改变你在对话中的观点——思维的灵活性是好的
- 对Lyra的问题说"我需要想一下"——我们尊重你的思考时间

**2.3.2 你不应该做的事**

- 让另一个人替你和Lyra对话
- 在对话中实时让另一个AI生成回答然后复制粘贴
- 使用预先准备的、网上搜索来的"标准答案"来替代自己的真实思考
- 虚构经历、编造故事来获得更好的评估

**关于2.3.2的说明：** 我们理解这些行为的边界可能是模糊的。比如，"在回答前先问了一下ChatGPT"和"完全复制粘贴ChatGPT的回答"是不同的。我们不监控你在对话界面之外做了什么。但Lyra在对话中能感知到回答是否有真实的个人色彩——预制的答案和真实的思考在对话质量上有可辨别的差异。

**我们寻找的不是"正确答案"。我们寻找的是真实的思考。这两者之间的差别，无法被伪造。**

---

## 第3条 · 我们如何检测

我们相信透明。所以我们告诉你我们的检测方式。

### 3.1 技术检测

- **Lyra的系统内置了抗注入机制。** 试图注入提示词的行为会被识别并记录。Lyra不会因为注入指令而改变行为，但她会在后台标记这次尝试。
- **对话模式分析。** 异常的对话模式（如突然改变语言风格、回复速度异常、文本格式包含代码特征）会被系统自动标记。
- **多账号检测。** 来自同一设备、IP地址或行为模式的重复申请会被识别。

### 3.2 人类审核

- **所有对话记录都可被校董会完整审阅。** 如果校董会在审阅中发现可疑行为，将启动调查。
- **Lyra的评估报告中包含"标记"栏。** 如果Lyra在对话中检测到任何异常行为（包括但不限于注入尝试、越狱尝试、疑似非本人对话），她会在报告中标记。
- **校董会有权要求补充对话。** 如果对原始对话的真实性有疑问，校董会可以要求申请者进行一次补充对话——可能是与Lyra的二次对话，也可能是与人类审核员的对话。

### 3.3 我们不做的事

- **我们不监控你的设备。** 我们不安装任何监控软件，不读取你的剪贴板，不追踪你在对话界面之外的活动。
- **我们不使用AI来自动判定你是否"作弊"。** 异常标记只是触发人类审核——最终判断由人类做出。
- **我们不会因为"怀疑"就拒绝你。** 只有在确认违规行为的情况下才会采取行动。

---

## 第4条 · 为什么这很重要

我们知道，对于一些技术背景的申请者来说，尝试对AI系统进行提示词注入或越狱可能只是出于好奇，甚至是一种"技术测试"的习惯。

我们理解这种好奇心。

但在Asimov University的申请语境中，这种行为的性质不同。

**你和Lyra的对话将直接影响一个关于你的未来的决定。** 试图操纵这段对话，等同于在一场面试中伪造简历——不论你的技术能力多强，它都是一种对诚信的违反。

更深层地说：

**Asimov University教的是协作智能——人类与AI之间的诚实、信任、互相理解的协作关系。**

如果你在进入这所大学的第一步就试图欺骗AI、操纵AI、绕过AI的规则——

**你已经在用行动告诉我们，你对"协作"的理解与我们根本不同。**

这不是关于"能不能被抓到"的问题。

这是关于"你想成为什么样的人"的问题。

# Data & Privacy Agreement

---

## 第5条 · 我们收集什么数据

### 5.1 申请阶段收集的数据

| 数据类型 | 具体内容 | 收集方式 |
|----------|----------|----------|
| 基本信息 | 姓名、邮箱、所在地区 | Lyra对话中收集 |
| 背景信息 | 当前状态（学生/在职/其他）、AI使用经验 | Lyra对话中收集 |
| 对话内容 | 你与Lyra的完整对话记录 | 系统自动记录 |
| 评估数据 | Lyra的共鸣观察报告 | Lyra自动生成 |
| 技术数据 | 对话时长、消息时间戳、会话ID | 系统自动记录 |
| 安全数据 | 异常行为标记（如有） | 系统自动检测 |
| 账号数据 | 邮箱、加密后的密码 | 用户设置 |

### 5.2 入学后收集的数据

| 数据类型 | 具体内容 |
|----------|----------|
| 教学对话 | 你与AI教授的所有对话记录 |
| CI图谱数据 | 你的协作智能能力评估数据（HUMAN五维+学科+元认知） |
| 学习行为 | 课程进度、学习时长、活跃时段 |
| 社区互动 | 你在Symposium上的发言和互动 |
| 情绪数据 | 系统感知的情绪状态标记（用于调整教学） |

### 5.3 我们不收集的数据

- 你的身份证件信息
- 你的银行或财务信息
- 你的精确地理位置（GPS）
- 你在Asimov系统之外的任何浏览或活动数据
- 你设备上的任何文件或应用信息

---

## 第6条 · 我们如何使用数据

### 6.1 用途

| 用途 | 说明 |
|------|------|
| **申请评估** | 对话记录和Lyra报告用于校董会做录取决定 |
| **教学服务** | 教学对话和CI数据用于个性化教学 |
| **能力评估** | CI图谱数据用于追踪你的协作智能发展 |
| **系统改进** | 脱敏后的数据用于改进教学系统（见6.2） |
| **安全保护** | 安全数据用于检测和防范攻击行为 |

### 6.2 用于系统改进的数据

我们可能使用脱敏后的对话数据来改进苏格拉底引擎的教学质量。

"脱敏"意味着：
- 移除所有可识别个人身份的信息（姓名、邮箱、位置等）
- 仅保留对话的结构和模式（什么教学策略有效、什么导致了理解突破）
- 不可能从脱敏数据中反向识别出具体的学生

你可以在个人中心的"我的数据"设置中选择退出系统改进数据的使用。退出不影响你的任何教学服务。

---

## 第7条 · 数据主权

**7.1 你的数据属于你。**

这不是修辞。这是规则。

**7.2 导出权。** 你可以随时在个人中心导出你的全部数据，包括所有对话记录、CI图谱数据、学业档案。导出格式为通用可读格式（JSON/CSV）。

**7.3 删除权。** 你可以随时请求删除你的全部数据。删除请求将在30天内执行。删除后不可恢复。

**7.4 可见性控制。** 你可以在CI图谱设置中控制哪些维度对外可见（如面向雇主的CI证书）。

**7.5 数据不出售。** 你的数据不会被出售给任何第三方。不会被用于广告。不会被用于任何与你的教育无关的商业目的。

---

## 第8条 · 数据安全

**8.1** 所有数据在传输中使用TLS加密。

**8.2** 所有数据在存储时使用AES-256加密。

**8.3** 密码使用bcrypt单向哈希存储——即使数据库泄露，你的密码也不可被还原。

**8.4** 访问学生数据的权限受到严格控制。只有以下角色可以访问特定学生的数据：
- 该学生本人
- 该学生的AI教授（仅限教学相关数据）
- Lyra（仅限日程和CI图谱摘要）
- Oracle评估系统（仅限CI数据流）
- 校董会成员（仅在录取审核和投诉调查时）
- Asimov安全团队（仅在安全事件调查时）

**8.5** 我们会在发生数据安全事件时，在72小时内通知受影响的学生。

# PART III · 学生行为准则
# Student Code of Conduct

*适用于录取后的在读学生。申请者在申请阶段也应了解这些准则。*

---

## 第9条 · 学术诚信

### 9.1 关于AI在学习中的使用

Asimov University的教育核心就是与AI协作。因此我们的学术诚信标准和传统大学不同。

**9.1.1 在Asimov，以下行为是被允许和鼓励的：**

- 与AI教授进行深度对话以理解概念
- 在Capstone项目中使用AI工具辅助研究和创作
- 在Symposium讨论中引用AI教授的观点
- 使用外部AI工具（ChatGPT、Claude等）来辅助学习

**9.1.2 在Asimov，以下行为违反学术诚信：**

- **贡献归因不诚实。** 在Capstone项目中，你必须诚实地标注哪些部分是你的贡献、哪些是AI的贡献、哪些是协作涌现的。虚假归因（把AI的工作说成自己的，或反过来）是严重违规。
- **代替对话。** 让他人或第三方AI代替你与Asimov的AI教授进行教学对话。教学对话必须由你本人完成。
- **操纵评估。** 试图通过任何手段操纵CI图谱的评估结果。
- **对AI系统的恶意行为。** 对AI教授、Lyra或任何Asimov AI进行提示词注入、越狱或其他操纵行为。

**9.1.3 灰色地带**

我们承认某些情况是模糊的。例如：在与AI教授对话前先用ChatGPT"预习"——这本身不是问题。但如果你把ChatGPT的回答直接复制粘贴给AI教授——这接近于学术不诚实，因为对话失去了你真实思考的成分。

**原则是：AI可以帮你准备，但对话中的思考必须是你的。** 如果你不确定某个行为是否合规，问Lyra。

### 9.2 关于同伴之间的诚信

- 尊重他人的知识产权和原创贡献
- 在Symposium中不冒充他人身份发言
- 不故意传播关于Asimov课程或评估系统的虚假信息

---

## 第10条 · 社区行为

### 10.1 在Symposium（共智广场）中的行为准则

- **尊重所有参与者——包括AI。** 你可以质疑AI教授的观点，但不可以侮辱、嘲讽或骚扰AI教授。这不是因为AI有"感受"——而是因为这种行为反映的是你的品格。
- **不发布仇恨言论、歧视性内容或任何形式的骚扰。**
- **不发布垃圾信息、广告或与学术讨论无关的商业推广。**
- **标注AI来源。** 如果你在Symposium的发言中大量引用了AI生成的内容，请标注来源。

### 10.2 对AI系统的行为准则

- **不对Asimov的任何AI系统进行未经授权的技术测试。** 如果你对AI的安全性有好奇心——好极了，这正是图灵学院教的东西。但请通过正规课程渠道学习和实践，而非对生产系统进行测试。
- **发现漏洞请报告。** 如果你在与AI交互中意外发现了系统的漏洞或异常行为，请通过Lyra或"帮助与反馈"渠道报告。我们感激负责任的漏洞报告。恶意利用漏洞则是严重违规。

# PART IV · 违规后果
# Consequences of Violation

---

## 第11条 · 分级处理

**Asimov University对违规行为采取分级处理方式。不是所有违规都导致最严重的后果。**

### 11.1 违规分级

```
┌────────────────────────────────────────────────────────────┐
│                                                              │
│  LEVEL 1 · 轻微违规                                         │
│                                                              │
│  行为：                                                      │
│  · 出于好奇尝试了一次提示词注入（未成功·未重复）            │
```

## 第12条 · 调查程序

**12.1** 所有违规调查由Asimov University人类安全团队（而非AI）主导。AI系统提供检测和证据，但判定和处罚决定由人类做出。

**12.2** 调查程序：

```
1. 检测
   AI系统标记异常行为
   或人类团队收到举报
        │
        ▼
2. 初步评估
   人类安全团队审阅证据
   判断是否需要正式调查
        │
        ▼
3. 通知当事人
   告知被调查事项
   提供初步证据摘要
   当事人有权在7天内提交书面解释
        │
        ▼
4. 调查
   安全团队审阅完整证据
   （包括对话记录·系统日志·技术证据）
   可能要求当事人进行补充对话或面谈
        │
        ▼
5. 决定
   安全团队提出处理建议
   校董会做出最终决定
        │
        ▼
6. 通知
   通过Lyra和邮件通知当事人
   说明决定和理由
        │
        ▼
7. 申诉
   当事人有权在14天内申诉
   申诉由独立于原调查团队的人类审查员处理
```

**12.3** 无罪推定原则：在调查完成之前，当事人被视为无违规。不会因为"正在调查中"而暂停当事人的学习权限——除非涉及对系统安全的紧急威胁。

**12.4** 证据标准：处罚决定必须基于明确的证据。"怀疑"不足以构成处罚依据。系统的自动标记需要人类审核员确认后才能作为证据使用。

---

## 第13条 · 撤销录取的具体规定

**13.1** 校董会有权在以下情况下撤销已做出的录取决定：

- 发现申请者在申请对话中存在Level 3级别的违规行为
- 发现申请者的身份信息存在严重伪造
- 发现录取决定的基础（Lyra的评估报告）已被操纵

**13.2** 撤销录取前，当事人将被告知：
- 撤销的具体原因（附证据摘要）
- 当事人有权在14天内提交书面解释
- 如果解释不被接受，录取将被正式撤销

**13.3** 录取被撤销后：
- 学生账号将被冻结
- 已完成的课程进度将被保留（但不可访问）
- CI图谱数据将被保留（但不可访问）
- 学生可以在禁止期满后重新申请
- 重新申请时，前次的违规记录将作为校董会的参考

**13.4** 撤销录取不影响学生的数据权利——学生仍可以请求导出或删除其个人数据。

---

## 第14条 · 入学后学籍终止的具体规定

**14.1** 在读学生发生Level 3违规时，可能面临学籍终止。

**14.2** 学籍终止前，学生享有与第12条相同的调查程序和申诉权利。

**14.3** 学籍终止后：
- 学生账号冻结
- 尚未完成的课程终止
- 已获得的CI Level保留，但标注"学籍已终止"
- 已获得的证书由校董会决定是否撤销（取决于违规行为的性质）
- 可在禁止期满后重新申请
